# Big Data Analytics — Project 1: From 2,000 Social-Media Records to a Marketing Decision

A Pakistani clothing brand posts on Instagram. The marketing team wants to know **which content gets attention and what to publish next**.
This project answers that with ordinary tools first (CSV + Pandas), then tests **what changes when data grows**, to justify when a scalable tool (Dask/Spark) is actually needed.

> **Data note:** the dataset in `data/` is **synthetic** (generated by `src/analysis.py`, seed 42) with realistic noise: missing values and duplicate rows. The engagement patterns (Reels, Bridal, evening slot) were built into the generator, so the findings demonstrate the **workflow, not real-world evidence**. Replace `data/social_media_posts.csv` with real data and re-run.

## Result (on the synthetic data)
Publish more **Reels** in the **Prime 19–22** slot, focused on **Bridal** content: average engagement **8.9%** vs **5.59%** overall.

## Workflow (10 steps)
| # | Step | What happens |
|---|------|--------------|
| 1 | Business question | Metric: engagement rate = (likes + comments + shares + saves) / reach × 100 |
| 2 | Load data | CSV into Pandas |
| 3 | Inspect | shape, dtypes, missing values, duplicates |
| 4 | Clean | drop duplicates, median-fill `caption_len`, drop rows with missing/zero reach (2,015 → 1,975 rows) |
| 5 | Features | engagement rate, weekday, posting time slot |
| 6 | EDA | group-by post type, category, time slot, weekday; correlations |
| 7 | Visualize | bar charts and a type × time-slot heatmap |
| 8 | Scale test | same groupby on 1x / 100x / 1000x data: time and memory |
| 9 | When to scale up | Pandas vs Dask vs Spark decision table (+ optional PySpark cell) |
| 10 | Recommendation | final decision, caveats, A/B test as next step |

## Key limitation
Pandas keeps all data in one machine's RAM. At ~2M rows the table already uses ~550 MB. For GB–TB data (multiple platforms, comment text, daily logs) a distributed tool such as Spark or Dask becomes justified. For ~2,000 rows it is not.

## Caveats
Correlation ≠ causation (Reels may simply get more algorithmic reach); one year of data only; promoted posts are not separated. Next step: a 4-week A/B test of Reels in the prime slot against a control group.
